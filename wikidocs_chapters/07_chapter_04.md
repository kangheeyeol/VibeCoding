# Chapter 04. 망하는 프롬프트 vs 흥하는 프롬프트 (목표, 제약조건, 페르소나, 출력형식)
## 1. 🎯 [디렉터 브리핑] 이번 챕터 미션
- AI에게 지시할 때 매번 결과물이 엉뚱하게 빗나가는 근본 원인을 파악합니다.
- 초보자의 막연한 질문을 일류 PM의 명확한 업무 지시서로 바꾸는 **'프롬프트 4원칙(R-T-C-O)'**을 익히고 실전에 적용합니다.
---
## 2. 💡 [1분 개념] AI는 '말귀 어두운 천재 인턴'입니다
AI는 전 세계 모든 프로그래밍 언어와 백과사전을 통째로 외운 천재입니다.  
하지만 동시에 **'눈치와 상황 판단력이 전혀 없는 신입 인턴'**이기도 합니다.
회사에서 인턴에게 *"점심 맛있는 것 좀 사 와"*라고 막연히 지시하면 어떻게 될까요?  
인턴은 자기가 제일 좋아하는 극도로 매운 마라탕을 사 올 수도 있습니다. 먹지도 못하고 돈만 날리게 됩니다.
반면, 훌륭한 팀장은 이렇게 지시합니다:
> *"오늘 손님이 오셨는데 매운 음식을 못 드셔(제약조건). 1인당 15,000원 예산 안에서 깔끔한 한식당 3곳을 찾아서(역할/과업), 식당 이름과 대표 메뉴, 도보 이동 시간을 표로 정리해 줘(출력 형식)."*
AI에게 코딩을 시킬 때도 완전히 똑같습니다. 막연하게 던지면 막연한 쓰레기(AI Slop)가 나오고, **명확한 제약조건과 함께 지시하면 감탄이 나오는 프로급 코드**가 탄생합니다.

## 3. 비교 분석: 망하는 프롬프트 vs 흥하는 프롬프트 (Before & After)

| 구분 | ❌ 망하는 프롬프트 (초보자) | ⭕ 흥하는 프롬프트 (프로 디렉터) |
| --- | --- | --- |
| **1. 신규 기능 추가** | "로그인 기능 하나 만들어줘." | "너는 보안에 엄격한 풀스택 엔지니어(Role)야. 루틴메이트에 이메일과 비밀번호로 로그인하는 모달 창(Task)을 만들어줘. 화면이 깜빡이지 않도록 팝업 형태로 띄우고, 비밀번호는 6자리 이상 검증 로직을 넣어줘(Constraints). 완성된 코드는 기존 헤더 컴포넌트와 자연스럽게 연결해줘(Output)." |
| **2. 버그 수정 요청** | "에러 나요. 왜 안 되죠? 고쳐주세요." | "체크박스를 클릭했을 때 브라우저 F12 콘솔에 'TypeError: Cannot read properties of undefined'라는 빨간 에러가 발생했어(Context). 습관 목록 데이터가 비어 있을 때 발생하는 문제 같아. 데이터가 로딩 중일 때 로딩 스피너를 보여주고, 안전하게 옵셔널 체이닝(?.)을 적용해서 에러를 해결해줘(Constraints)." |
| **3. 디자인 스타일링** | "요즘 유행하는 스타일로 예쁘게 바꿔줘." | "2026년 미니멀리즘 테크 스타일로 스타일을 변경해줘(Role). 카드 배경은 연한 슬레이트 그레이(bg-slate-50), 테두리는 얇은 회색(border-slate-200), 모서리는 둥글게(rounded-2xl) 처리하고, 포인트 컬러는 에메랄드 그린(emerald-500)을 적용해줘(Constraints)." |

## 4. 📋 [치트키] 비개발자 전용 프롬프트 4원칙: RTCO 공식
AI에게 지시를 내리기 전, 머릿속으로 다음 4글자만 기억하세요.
```plain text
1. [R] Role (역할)       : 너는 누구인가? (예: "너는 시니어 React 디자이너 겸 개발자야")
2. [T] Task (과업)       : 지금 무엇을 만들어야 하는가? (예: "오늘 달성률을 보여주는 프로그레스 바를 만들어줘")
3. [C] Constraints (제약) : 절대 어겨서는 안 되는 조건은 무엇인가? (예: "390px 모바일 너비 유지, 초록색 사용")
4. [O] Output (출력)     : 어떤 형태로 납품해야 하는가? (예: "기존 코드를 통째로 바꾸지 말고, 변경된 함수 부분만 알려줘")
```
